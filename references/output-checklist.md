# cdtest 输出检查清单

交付前必须逐项自检。

---

## 运行模式

- [ ] 已根据用户输入判断模式（设计模式/执行模式/混合模式）
- [ ] 设计模式下：主要产出为 Phase 1（需求解读 + 用例生成）
- [ ] 设计模式下：Phase 2~4 章节已保留占位说明（明确标注已按开关跳过）
- [ ] 设计模式下：没有声称已经执行测试、截图或生成日志
- [ ] 执行模式下：已确认环境就绪（参考 Phase 0 检查清单）

---

## 历史资料召回

- [ ] 已读取并匹配 `references/historical-case-index.md`
- [ ] 已说明历史资料是否命中
- [ ] 已区分历史已有逻辑、本期新增逻辑、本期修改逻辑、保持不变逻辑
- [ ] 已说明影响模块和影响原因
- [ ] 已列出待确认问题
- [ ] 回归用例能说明来源（来自哪个历史模块或风险点）
- [ ] 没有把无关历史模块硬塞进回归范围

---

## 产品需求解读

- [ ] 已总结当前新需求的业务目标
- [ ] 已描述用户路径（从哪里进入、做什么、结果是什么）
- [ ] 已分析影响范围（页面/接口/配置/数据/商业化链路）
- [ ] 已列出待确认问题

---

## 测试方案

- [ ] 已输出测试范围、范围外、重点新功能、重点回归
- [ ] 已输出测试数据要求（账号/书籍/VIP状态/广告配置/环境等）
- [ ] 已输出环境、Core、APP语言、APP版本号、服务端版本号规则
- [ ] 已输出风险和待确认问题
- [ ] 设计模式下已生成 Word `.docx` 测试方案文件
- [ ] 最终回复中已给出测试方案 Word 文件绝对路径

---

## 测试用例

- [ ] 已输出新功能测试用例（覆盖当前新需求新增/修改能力）
- [ ] 已输出回归测试用例（覆盖新需求影响到的历史功能）
- [ ] 每条用例包含 **完整字段**（见 case-template.md 对应平台模板）
- [ ] 字段值符合值域约束（见 case-template.md 字段规则）

### Web 用例检查

- [ ] 浏览器 = Chrome
- [ ] 分辨率已明确

### APP 用例检查

- [ ] `Core` 仅使用 `全部/1/2/3/4/5` 或其多选组合，如 `2/3`
- [ ] `APP语言` 仅使用 `全部/英/西/葡/法/俄/印尼/泰/繁/日` 或其多选组合，如 `英/法`
- [ ] `APP版本号` 已区分 iOS 三位版本与 Android 三位/四位版本
- [ ] `测试环境` 仅使用 `全部/内网/预发/外网` 或其多选组合
- [ ] `用户状态` 仅使用 `普通用户/VIP用户/SVIP用户/新福利包用户` 或其多选组合
- [ ] `服务端版本号` 为纯数字；无法确认时写 `待确认`，没有留空

### 通用检查

- [ ] 步骤可人工执行，未来可转自动化
- [ ] 设计模式下已生成 Excel `.xlsx` 测试用例文件
- [ ] 最终回复中已给出测试用例 Excel 文件绝对路径

## 混合模式特有检查

- [ ] 已明确识别混合意图（Web 后台 + APP 前端）
- [ ] 已确认 Web 和 APP 在同一测试环境（同一 DB/同一 API Base）
- [ ] 混合模式下 `APP_AI_EXECUTION_ENABLED` 开关已忽略（强制执行）
- [ ] Web 管理登录凭证和 APP 用户登录凭证均已配置
- [ ] Web 后台配置操作已截图 + DB 记录
- [ ] 配置生效已确认（DB 直查 / API 验证）
- [ ] APP 端验证操作已截图 + 结果记录
- [ ] Web ↔ APP 切换时，不使用的 session 已释放
- [ ] 混合报告已包含：Web 配置记录 + APP 验证结果 + 数据链路追踪
- [ ] Web 配置类操作：❌ 不清理（留待人工确认）
- [ ] APP 测试数据：✅ 已按【测试】标记清理
- [ ] 权益变更：⚠️ 已恢复原态
