## 零、四条铁律（违反即返工）

1. **密钥只走环境变量**：`$env:TTS_SECRET_KEY = '<key>'`。不得写入脚本、文档、报告、批次目录或 git；发现疑似泄露立即上报。
2. **未经明确允许不得删除任何数据**（含自己跑出来的批次、日志、诊断输出）。磁盘不足先申请。
3. **改任何文件前先快照**：`powershell -NoProfile -File 07_流程工具\create_iteration_backup.ps1 -Name <迭代名> <路径...>`。
4. **`taskStatus=2` ≠ 通过**：成功只代表有产物，必须独立跑 M1（文本口径）与 M5（字幕完整性）比对后才能下结论。

## 一、任务执行流程（标准作业程序 SOP）

> 每一步都有：**入口脚本 → 输入 → 产物 → 落盘位置 → 通过判据**。任一步判据不通过，**不得进入下一步**。

| # | 步骤 | 入口 | 输入 | 产物与落盘位置 | 通过判据 |
|---|---|---|---|---|---|
| 0 | **准备与自检** | 手工 | 环境 | `00_开始这里\环境说明.md` 的自检清单逐条打勾 | Python≥3.10 / 依赖 / ffmpeg / ASR 模型 / 磁盘≥20GB |
| 1 | **取物料** | `02_脚本\1_语料\`（`fetch_haiyue_book_text.py` 或 `build_ja_ko_5000char_material.py`） | 海阅书库 / `03_输入\源语料\` | 新语料 → `03_输入\预置语料\<语种>_<版本>\material\` | 每单元 ~5000 字符且**保留段落换行**；`units.jsonl` 齐备 |
| 2 | **M0 门禁 + 探活** | `02_脚本\9_诊断\_probe_paragraph_once_0924.py --lang ja --unit 1` | 语料单元 | 控制台结果 + `05_运行输出\段落格式验证_0924\` | `taskStatus=2` 且 **`distinct paraIndex > 1`**、无 >200 字超长段、无 81.64s 段 |
| 3 | **接口用例**（正/逆向） | `02_脚本\2_执行\run_text_format_cases_0924.py --lang ja --workers 4 --out-suffix _r1` | 预置语料 | `05_运行输出\文案格式用例_0924_r1\{src,meta,results.json}` | 正常用例全 PASS；FAIL 必须写成缺陷条目 |
| 4 | **稳定性/性能跑批** | `02_脚本\2_执行\run_higgs_ja_ko_10concurrent_30min.py --lang ja --workers 10 --minutes 30 --dir-name <批次>` | 批次目录自带 `material\` | `05_运行输出\<批次>\{src,meta,srt,audio,tasks.jsonl,summary.json,progress.log}` | 成功率 ≥99%；失败任务留 taskId；**看 `progress.log` 而非控制台** |
| 5 | **分析** | `02_脚本\3_分析\analyze_ja_ko_perf_0924.py`、`audio_quality_ja_ko_0924.py [--refetch]`、`asr_accuracy_ja_ko_largev3_0924.py` | 上一步批次 | `<批次>\analysis\{perf_m1_m5.json,audio_m2.json,audio_listen_checklist.md}`、`05_运行输出\analysis_ja_ko_asr_m3\` | M1 缺失 0；M5 空字幕/SRT≠segments 0；M2 无长空洞；**跑批期间不得在本机做重解码/ASR** |
| 6 | **报告** | `02_脚本\4_报告\gen_report_*.py` | 分析产物 | `05_运行输出\报告\*.md` | 按主技能「报告交付规范 13 项」逐条打勾 |
| 7 | **交付包（可选）** | `02_脚本\5_交付\export_*_pack_*.py` | 批次 + 分析 | `05_运行输出\开发分析包_*\`（可打包 zip 给开发） | 每条缺陷都有「现象/证据/影响/分级/建议」 |
| 8 | **入库留档** | `07_流程工具\sync_tingju_skill_to_git.ps1 -DryRun` → `-Push` | 文档/报告/脚本 | git 分支 | `-DryRun` 清单核对无误；守卫通过（无密钥/无大文件） |
| 9 | **回归** | 见 §四 | 本轮批次 | 回归记录（写进报告缺陷节） | 8 项回归逐条有结论（**未复现也要记录**） |

## 二、脚本生成规范

### 2.1 命名

| 类型 | 约定 | 示例 |
|---|---|---|
| 当前链路可复用脚本 | `<动作>_<对象>[_<日期>].py` | `run_higgs_ja_ko_10concurrent_30min.py`、`audio_quality_ja_ko_0924.py` |
| 报告生成器 | `gen_report_<主题>[_<日期>].py` | `gen_report_stability_0924.py` |
| 交付包导出 | `export_<受众>_<主题>[_<日期>].py` | `export_dev_pack_round2_0924.py` |
| 一次性诊断 | `_<动作>_<对象>[_<日期>].py`（`_` 前缀＝一次性） | `_probe_paragraph_once_0924.py` |
| 历史/遗留 | 不新增；旧脚本不纳入新流程 | — |

### 2.2 必须包含的结构（缺一不可）

```python
# 1) 统一路径：从 02_脚本\paths.py 取，不要在脚本里写绝对路径
import sys as _sys
from pathlib import Path as _Path
_sys.path.insert(0, str(_Path(__file__).resolve().parents[1]))     # → 02_脚本
from paths import PKG, SPEC, SRC_CORPUS, PRESET, DATA, RUNS, REPORTS, MODEL_LARGE_V3  # noqa: E402

# 2) 凭据：只从环境变量取；模块级不报错（纯本地分析无需密钥），调用接口前才校验
_TTS_KEY = os.environ.get("TTS_SECRET_KEY")
def _require_key(): ...

# 3) 入口：CLI + 帮助；所有可调参数（并发/时长/批次名/语种）都要能传参
def main(): ...
if __name__ == "__main__":       # 4) 必须有 main 保护，禁止 import 即执行
    main()
```

### 2.3 留证与日志要求

- **落盘位置只用 `RUNS`（`05_运行输出`）**，不得写到规范区/输入区；
- 每任务至少留：`src\task_XXXX.txt`（真实下发文案）、`meta\task_XXXX.json`（接口返回）、`srt\`、`audio\`、`tasks.jsonl`（逐任务指标）、`summary.json`、`progress.log`；
- 跑批类脚本必须**增量写 `tasks.jsonl`** 且进度写 `progress.log`（后台运行时控制台是块缓冲，不可依赖 stdout）；
- 分析类脚本把结论落 `<批次>\analysis\*.json` + 人读的 `*.md`。

### 2.4 禁止项（Review 直接打回）

| 禁止 | 原因 | 正确做法 |
|---|---|---|
| 硬编码密钥 | 泄露风险 | 环境变量 + 惰性校验 |
| 硬编码绝对路径（`D:\...`/`E:\...`） | 换机即坏 | `paths.py` |
| 写死历史批次目录（如 0924） | 数据不在本包，运行即报错 | 参数化 `--run-dir`；缺数据时给出明确提示 |
| import 即执行（无 `main` 保护） | 被 import/检查时误触发副作用 | `if __name__ == "__main__":` |
| 跨脚本 `import` 复用 | 分组迁移后路径易断 | 提取到 `paths.py` 或新脚本 |
| 输出写到规范区/输入区 | 破坏"只读区"约束 | 一律写 `RUNS` |

### 2.5 新脚本入库

1. 放到 `02_脚本\<分组>\`；
2. `py_compile`/AST 自检 + 无密钥下 `--help` 自检；
3. 加进 `07_流程工具\tingju_script_allowlist.txt`（白名单）→ `sync_tingju_skill_to_git.ps1 -WithScripts -DryRun` 核对 → `-Push`；
4. 守卫会拦：密钥特征、>2MB、音频/压缩后缀。

## 三、物料获取与存放规范

### 3.1 放哪个文件夹（唯一答案表）

| 物料 | 唯一存放位置 | 说明 |
|---|---|---|
| 书籍原文 / 源语料 | `03_输入\源语料\` | 由海阅技能或人工提供，只增不改 |
| 预置语料（M0 合规，可直接跑） | `03_输入\预置语料\<语种>_<版本>\material\` | 例：`日语_r3\material\` |
| 练习数据（离线练分析） | `04_示例数据\练习数据\<语种>_N任务\` | 含真实音频，供新人上手 |
| 证据示例（用例真实返回等） | `04_示例数据\证据示例\` | 只读参考 |
| **跑批批次（含音频）** | `05_运行输出\<批次>\` | 唯一产物落点 |
| 分析产物 | `<批次>\analysis\` | 由分析脚本生成 |
| 报告 | `05_运行输出\报告\` | 新生成报告；历史报告在 `01_规范与用例\历史报告\`（只读） |
| 交付包 | `05_运行输出\开发分析包_*\` 或 `人工听测包_*\` | 成品可另存 `06_交付示例\` |
| 诊断输出 | `05_运行输出\诊断_*\`、`05_运行输出\段落格式验证_*\` | 一次性结论 |
| 规范/技能/文档 | `01_规范与用例\`（含 `依赖技能\`、`治理规范\`） | **只读区**，不得放产物 |
| 脚本 | `02_脚本\<分组>\` | **只读区**，除新增脚本外不改 |
| ASR 模型 | `tools\whisper_models\` | 大文件，禁止复制到别处 |

### 3.2 命名规范

| 对象 | 规则 | 示例 |
|---|---|---|
| 批次目录 | `<模型/链路>_<语种>_<用途><并发>x<时长>_<日期>[_<轮次>]` | `Higgs_日语_稳定性10并发_30min_0924_r3` |
| 语料版本 | `<语种>_<语料轮次>`（r3＝保留段落的合规轮次） | `日语_r3` |
| 报告 | `<主题>_<语种或范围>_<日期>.md` | `日韩_稳定性10并发_30min_20260924.md` |
| 交付包 | `开发分析包_<主题>_<日期>\` / `人工听测包_<主题>_<日期>\` | `开发分析包_接口与稳定性_0924\` |

### 3.3 物料获取方式（按优先级）

1. **已有预置语料**（最快）：直接复制 `03_输入\预置语料\<语种>_r3\material` 到批次目录；
2. **从书库拉新语料**：用依赖技能 `01_规范与用例\依赖技能\haiyue-book-text-fetch\`（`scripts\get_token.py` → `scripts\fetch_book_text.py`），产物落 `03_输入\源语料\`；
3. **从源语料切合规单元**：`build_ja_ko_5000char_material.py`（**必须保留段落换行**），产物落 `03_输入\预置语料\`；
4. **外部提供**：先放入 `03_输入\源语料\`，再走 3；**不得**直接塞进批次目录。

### 3.4 留证与生命周期

- 每批次至少保留：`material\`、`src\`、`meta\`、`srt\`、`audio\`、`tasks.jsonl`、`summary.json`、`progress.log`、`analysis\`；
- 体积预算：**30 分钟 × 10 并发 ≈ 0.4~0.5 GB/语种**（5000 字任务）；跑批前确认磁盘 ≥20 GB；
- 清理：**必须经批准**；建议只清 `audio\`（保留 `tasks.jsonl`+`meta\`+`analysis\` 即可复现结论），清前把清单提交负责人。

- 语料变更（换书、换语种、语料格式调整）；
- 测试脚本或有依赖的 `paths.py` 变更；
- 距上次验收超过 **14 天**；
- 常规周期性验收（每轮跑批收尾必做 1~8 中的 **2、3、4、5、6** 项，1、7、8 可按需）。

## 六、常见"放错地方"与纠正

| 现象 | 正确做法 |
|---|---|
| 跑批产物落在 `01_规范与用例\` 或 `02_脚本\` | 改脚本输出到 `RUNS`；把误建目录清理（需批准） |
| 新语料直接放进批次目录，没有进 `03_输入\` | 先入 `03_输入\预置语料\`，批次目录只是一次运行的副本 |
| 报告散落在批次目录 | 报告统一 `05_运行输出\报告\`；历史报告在 `01_规范与用例\历史报告\`（只读） |
