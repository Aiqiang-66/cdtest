# 混合模式执行引擎 — AI 驱动版

## 定位

AI 自主调度 Web 和 APP 的执行、管理跨平台切换、生成融合报告。**不预设执行模板**。

## AI 判断框架

```yaml
# AI 在混合执行时自动执行以下流程：
1. 调度执行:
   - AI 根据混合子模式决定执行顺序：
     - 配置驱动型: Web(配置) → 生效确认 → APP(验证)
     - 独立并行型: Web(独立) → APP(独立)（AI 判断哪个先执行更快）
     - 数据链路型: Web(操作) → DB(确认) → APP(验证) → DB(再确认)
   - AI 在切换平台时自动释放不使用的 session

2. 管理跨平台切换:
   - Web → APP 切换时：
     - 关闭 Web session（释放资源）
     - 启动 APP session
     - 传递共享数据（DB 状态/测试账号）
   - APP → Web 切换时：
     - 关闭 APP session
     - 启动 Web session
     - 验证 Web 端数据是否反映 APP 操作

3. 对比跨平台结果:
   - AI 自动对比 Web 和 APP 的同一功能：
     - 功能是否一致？（Web 搜索 5 条，APP 搜索 5 条）
     - 数据是否一致？（Web 显示状态 A，APP 显示状态 A）
     - UI 是否一致？（布局/文案/交互方式可能不同，AI 判断哪些差异是合理的）
   - AI 输出对比结果 + 差异分析

4. 生成融合报告:
   - AI 根据执行情况动态生成报告：
     - Web 配置记录
     - APP 验证结果
     - 配置链路追踪
     - 数据一致性检测
     - 清理记录
     - 整体结论
```

## AI 执行示例

```yaml
场景: "配置广告位 → APP 验证"
AI 执行:
  阶段1: Web 配置
    - 登录管理后台 → 进入广告位管理 → 创建"【测试】首页Banner" → 保存
    - 截图: web_config_ad_banner.png
    - DB 确认: SELECT * FROM ad_config WHERE name LIKE '%【测试】%' → 已写入

  阶段2: 配置生效确认
    - DB 直查: ad_config.status = 'active' → 已生效
    - API 验证: GET /api/ad/config → 返回新广告位 → 已生效

  阶段3: APP 验证
    - 启动 APP → 登录测试账号 → 进入首页
    - 检查: 首页顶部展示 Banner 广告
    - 点击: 广告可点击跳转
    - 截图: app_verify_ad_banner.png

  阶段4: 清理
    - APP 测试数据: 自动清理（标记【测试】）
    - Web 配置: ⚠️ 记录到清理清单，不自动清理
      → 测试完成后列出所有 Web 配置变更，提示用户确认是否批量清理
      → 如 3 次以上运行未清理 → 提示用户考虑创建配置清理脚本

  报告:
    - Web 配置: ✅ 成功创建广告位
    - APP 验证: ✅ 广告展示正常，点击跳转正常
    - 链路追踪: Web→DB→APP 一致
    - 结论: PASS
```

## AI 资源调度

```yaml
# AI 在混合执行时自主调度资源：
资源调度:
  - Web 配置期间: APP session 未启动 → 不占用资源
  - 配置生效等待期间: AI 判断是否可以执行其他无依赖的 APP 用例
  - APP 验证期间: Web session 已关闭 → 释放资源
  - 目标: 最小化总执行时间，最大化资源利用率
```
