# 混合模式路由规则 — AI 驱动版

## 定位

AI 自主判断是否需要混合执行、选择混合模式、调度执行顺序。**不预设路由规则表**。

## AI 判断框架

```yaml
# AI 在收到用户输入时自动判断：
1. 是否混合模式:
   - AI 分析用户输入是否同时涉及 Web 和 APP
   - 判断依据：是否提到"Web后台+APP"、"配置+验证"、"管理后台+APP效果"
   - 是 → 进入混合模式
   - 否 → 进入单一平台模式

2. 选择混合子模式:
   - AI 根据上下文判断：
     - 配置驱动型: "先在 Web 后台配置 XX，再到 APP 验证效果"
     - 独立并行型: "Web 端和 APP 端都要测，没有依赖关系"
     - 数据链路型: "验证 Web 操作后 APP 端数据是否同步"
   - AI 不预设模式表，每次根据上下文动态判断

3. 调度执行顺序:
   - AI 根据依赖关系决定：
     - 配置驱动型: Web(配置) → APP(验证)
     - 独立并行型: 先 Web 后 APP（或反之，AI 判断哪个更快）
     - 数据链路型: Web(操作) → DB(确认) → APP(验证) → DB(再确认)
```

## AI 执行示例

```yaml
用户输入: "帮我配置广告位然后在APP上验证展示效果"
AI 推理:
  - 模式: 混合模式（配置驱动型）
  - 执行顺序:
    1. Web 后台: 登录管理后台 → 进入广告位管理 → 开启新广告位 → 截图 + DB 记录
    2. 配置生效确认: DB 直查 ad_config 表 → 确认已写入
    3. APP 验证: 启动 APP → 登录 → 进入首页 → 检查广告位展示 → 截图
    4. 清理: APP 测试数据清理，Web 配置不清理
  - 报告: 混合报告（Web 配置记录 + APP 验证结果 + 链路追踪）

用户输入: "验证跨端数据一致性，Web后台和APP双端"
AI 推理:
  - 模式: 混合模式（数据链路型）
  - 执行顺序:
    1. Web 操作: 在管理后台修改书籍榜单排序
    2. DB 确认: 查询榜单配置表 → 确认排序已更新
    3. APP 验证: 打开 APP 书城 → 检查榜单排序是否与 Web 配置一致
    4. DB 再确认: 再次查询 → 确认数据一致性
  - 报告: 混合报告 + 数据链路追踪
```

## AI 数据传递决策

```yaml
# AI 在跨平台传递数据时自主决策：
数据传递:
  - 用户凭证: Web 管理账号 ≠ APP 用户账号 → 不混用
  - 配置状态: Web 配置后查 DB → APP 验证前从 DB 读
  - 测试账号: Web 创建 → APP 使用同一账号
  - 测试数据: 标记 【测试】 → 双端共享
  - AI 判断: 什么数据可以共享？什么数据不能共享？
```

## AI 环境一致性检查

```yaml
# AI 在执行前自动检查环境一致性：
环境检查:
  - Web 和 APP 是否在同一测试环境？
  - DB 是否可直连？
  - API Base URL 是否一致？
  - 不一致 → AI 提示"环境不一致，可能导致数据不通"
```
