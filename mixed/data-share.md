# 混合模式：数据共享策略 — AI 驱动版

## 定位

AI 自主判断跨平台数据如何共享、如何传递、如何清理。**不预设数据传递矩阵**。

## AI 判断框架

```yaml
# AI 在混合模式下自动管理数据共享：
1. 识别数据类型:
   - AI 分析当前操作涉及的数据类型：
     - 配置类（广告位/福利包/审核模式）→ 不清理
     - 权益类（VIP/订阅）→ 恢复原态
     - 业务类（用户/订单/书籍）→ 标记 【测试】 → 清理
   - AI 不预设类型表，每次根据上下文动态判断

2. 选择共享方式:
   - AI 根据数据类型选择：
     - 配置类 → DB 写入 → APP 读取
     - 权益类 → API 发放 → APP 刷新
     - 业务类 → 共享账号池 → 双端使用
   - AI 不预设共享方式，每次根据场景动态选择

3. 管理数据状态:
   - AI 在操作前后自动记录数据状态：
     - 操作前: SELECT 当前状态
     - 操作后: SELECT 新状态
     - 对比: 状态是否按预期变化？
   - AI 生成数据状态追踪表

4. 执行清理:
   - AI 根据数据类型决定清理策略：
     - 配置类 → 不清理（留待人工确认）
     - 权益类 → 恢复原态
     - 业务类 → 自动清理
   - AI 清理前输出清理清单
```

## AI 数据状态追踪示例

```yaml
场景: "配置广告位 → APP 验证"
AI 数据追踪:
  - 数据类型: 配置类
  - Web 操作: 创建广告位 "【测试】首页Banner"
  - DB 状态: ad_config 表新增记录，status='active'
  - APP 验证: 首页展示 Banner 广告，点击跳转正常
  - 清理: ❌ 不清理（配置类，留待人工确认）
  - 风险: 低（测试广告位不影响生产数据）

场景: "发放 VIP 权益 → APP 验证"
AI 数据追踪:
  - 数据类型: 权益类
  - Web 操作: 给用户 "test_user_001" 发放 7 天 VIP
  - DB 状态: user_vip 表新增记录，expire_time=7天后
  - APP 验证: 用户显示 VIP 标识，可访问 VIP 专享内容
  - 清理: ⚠️ 恢复原态（删除 VIP 记录）
  - 风险: 中（权益变更影响用户体验）
```

## AI 配置生效等待

```yaml
# AI 在配置生效时自主检测：
生效检测:
  - 优先级1: DB 直查（最快，AI 直接查询配置表）
  - 优先级2: API 验证（调业务 API 检查配置接口）
  - 优先级3: APP 刷新（强刷新后检查 UI）
  - 优先级4: 等待+重试（已知有缓存延迟时）
  - AI 动态选择：哪个方式在当前场景下最快？
```
