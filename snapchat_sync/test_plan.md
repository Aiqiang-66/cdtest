## 2. 产品需求解读

| 维度 | 解读 |
|------|------|
| 业务目标 | 在素材报表中支持将素材同步至 Snapchat 媒体渠道 |
| 用户路径 | 素材报表 → 代号搜索(XY14) → 选择SC媒体 → 勾选素材 → 点击同步 → 选择目标媒体 → 确认同步 → 查看同步状态/审核列表 |
| 历史已有逻辑 | 素材同步功能已支持其他媒体(FB/TT/GG等)，MaterialSyncTask/MaterialSyncSubTask 表结构已存在，同步审核列表功能已存在 |
| 本期新增逻辑 | ① Snapchat 作为同步来源/目标媒体渠道；② SC单向同步限制（前后端均需校验，SC来源不可同步回其他媒体）；③ SC同步栏状态更新；④ 同步审核列表展示 C1-Snapchat 数据(C1→Core=1) |
| 本期修改逻辑 | 素材报表媒体下拉框新增 Snapchat 选项；同步栏状态针对 SC 渠道更新 |
| 保持不变逻辑 | 其他媒体(FB/TT/GG等)之间的同步逻辑保持不变；同步审核列表的通用展示逻辑不变 |
| 待确认逻辑 | 无（全部已确认） |

## 3. 已确认项 ✅

| 确认项 | 结论 | 影响 |
|--------|------|------|
| SC单向限制校验层级 | **前后端均需校验** | 需增加API层拦截验证用例 |
| C1→Core映射 | **C1 → Core=1** | 数据验证时使用 Core=1 |
| 同步审核列表 | **需要审核流程** | 测试需覆盖审核流转 |
| SC重复同步到相同目标 | **拦截提示** | TC-SCS-013 预期结果明确 |

## 4. 测试范围

| 类型 | 范围 |
|------|------|
| 范围内 | ① SC媒体下拉选择 ② SC作为来源同步到其他媒体 ③ 其他媒体同步到SC ④ SC→其他媒体被拦截(前后端) ⑤ 同步栏状态更新 ⑥ 同步审核列表及审核流程 ⑦ 数据库数据一致性 |
| 范围外 | SC广告投放、SC账号管理、SC API对接稳定性 |
| 重点新功能 | SC媒体选框、SC单向同步限制(前后端)、同步审核列表C1-Snapchat展示 |
| 重点回归 | 其他媒体(FB/TT)间互相同步不受影响、代号搜索XY14正常、素材勾选同步完整链路 |

## 5. 测试策略

| 策略 | 说明 |
|------|------|
| 新功能测试 | 覆盖SC素材选择→同步→状态更新→审核列表→审核流程全流程 |
| 回归测试 | ① FB/TT之间互相同步不受SC新增影响 ② 代号搜索XY14功能正常 ③ 素材勾选→同步→DB验证完整链路 |
| 异常场景测试 | SC→其他媒体同步前后端拦截提示、空勾选同步、SC素材已同步再次同步拦截 |
| 数据状态测试 | MaterialUploadLog.SourceChlType=SC, MaterialSyncTask.Status, MaterialSyncSubTask.Status, Core=1 |
| 界面测试 | 媒体下拉框SC选项展示、同步栏SC状态更新、审核列表C1-Snapchat展示 |

## 7. 风险

| 类型 | 内容 | 影响 | 建议处理 |
|------|------|------|----------|
| 风险 | SC API 对接延迟或不稳定可能影响同步成功率 | 同步任务可能长期pending或失败 | 增加同步重试机制的验证 |
| 风险 | 后端单向限制校验逻辑实现不完整 | 可通过API直接绕过限制 | 验证后端API层存在相同校验 |
