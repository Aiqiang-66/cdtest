## 一、测试目的与口径

| 项 | 内容 |
| --- | --- |
| 测试目的 | 验证并发下发时，**接口返回的输出文案与下发提交的输入文案是否一致、是否丢词** |
| 比对对象 | 输入：下发提交的 `read_content`；输出：接口返回 metadata 的文本（即字幕文本） |
| 比对方式 | 归一化（NFKC / 统一引号 / 去首尾标点 / 小写）后按词序列比对，`delete/replace` 记为缺失词，`insert/replace` 记为多余词 |
| 严格度补充 | 另做字符级比对：压缩空白后逐字符比对、去除标点与大小写后逐字符比对 |
| 文案来源 | 英语小说 `XR3 - EN.txt` 滑窗切成互不相同的文案 |
| 数据范围 | 仅本次晚间下发批次，不含其他时段数据 |

## 四、结论

1. 晚间 208 个并发任务（5 路并发持续打满 30 分钟）**输入与输出文案逐词完全一致**，缺失词 0、多余词 0，缺失率 0.000%。
2. 补充口径 30 个长文案任务（1500 词）同样零缺失，说明长文案不影响文案完整性。
3. 全程未出现文案丢失、串词或返回内容与请求内容不匹配的情况；输出文案词数与输入一致。
4. 输出与输入的唯一差异是省略号 `...` 的拼接写法（`.. .`），属于文本格式化差异，不影响内容完整性。
5. 性能侧：创建接口耗时平均 0.04s（最小 0.019s / 最大 0.477s），端到端耗时 P50 42.5s / P90 51.7s，5 路并发持续 30 分钟无排队恶化，吞吐 6.87 任务/分钟。
