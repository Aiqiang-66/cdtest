# TTS 接口（产出 MP3 文件）—— 补充测试场景清单

> **为什么需要这份清单**：`POST /Video/CreateUniversalTransparent`（`taskType=74`）的交付物不是一句"合成成功"，
> 而是**一条完整产物链**：
>
> ```
> read_content ──切句/分段──> 分段合成 ──编码──> MP3 文件（落 COS）──> audio_url（时效签名）
>                                              └──> metadata.json / SRT ──> metadata_url（时效签名）
> ```
>
> 因此测试面 = **内容正确性 + 文件本体 + 存储分发 + 链接时效 + 任务生命周期 + 成本与安全**。
> 现有 `文案格式_正常与异常_0924.md` 只覆盖了"**内容/切句**"这一层，其余各层见本清单。
>
> **依据**：`SKILL.md` v1.1.6（M0~M5）｜批次：0924 日语/韩语 10 并发 × 30 分钟、r2/r3 复跑

## 〇、当前产物的实测基线（可作为断言的对照）

| 项 | 实测值（0924 日语批次，94 个 MP3） |
|---|---|
| 容器 / 编码 | MP3（PyAV 解码为 `mp3float`，实际为 24 kHz / mono / fltp 解码格式） |
| 采样率 / 声道 | **24000 Hz / 单声道** |
| 码率 | **≈51 kbps**（逐文件 48.9~52.3 kbps，**VBR**） |
| 体积 | 5000 字任务 ≈ **3.92~4.70 MB**（中位 4.50 MB），时长 ≈ 12 分钟 |
| 标签 | 容器仅 `encoder = Lavf60.16.100`（服务端用 ffmpeg 封装）；**无 title/artist/album** |
| 时长一致性 | 音频时长 vs metadata 末段 `endMs` 差 **≤63 ms** |
| 峰值 / 响度 | 日语 **1.111~1.232（越界）**、RMS −11.46 dBFS；韩语 0.99~1.075、RMS −16.52 dBFS |
| 高频占比（≥8kHz） | 14%~18%（阈值 10%） |
| 产物链接 | `audio_url` → `reader-audio-1382266829.cos.ap-hongkong.myqcloud.com/audiobook/<taskId>.mp3`（**香港**）；`metadata_url` → COS **广州**（带 `q-sign` 时效签名） |
| 命名规则 | **`<taskId>.mp3`**（可预测、可枚举） |
| 已发现缺陷 | 产物可见性竞态（NoSuchKey 18/225）、81.64s 静默占位、任务卡死 32 分钟、削波 |

## 一、MP3 文件本体（TC-ART-*）

> 交付物是文件，**先保证这个文件"是个合法、完整、可播、参数正确的 MP3"**。

| ID | 场景 | 方法 | 判据 | 现状 |
|---|---|---|---|---|
| TC-ART-001 | 编码参数符合约定 | `ffprobe -show_streams` 逐文件 | 采样率/声道/码率在约定范围（当前 24k/mono/≈51k） | 已有基线，未固化用例 |
| TC-ART-002 | **可解码性与播放器兼容性** | ffmpeg / PyAV / 浏览器 `<audio>` / 手机播放器 | 全部能正常解码播放，无"文件损坏" | 未测 |
| TC-ART-003 | **时长一致性** | 音频时长 vs metadata 末段 `endMs` | 差 <1s（当前 ≤63ms ✅） | 已侧测，未固化为用例 |
| TC-ART-004 | **首尾完整性** | 听首 3s / 末 3s；核对首字与末字是否完整 | 首字不吞、末字不截断；末尾无异常拖尾静音 | 未测（**高发**） |
| TC-ART-005 | ID3/标签规范性 | 读 ID3v2 头 | 是否需写入 `title=chapter_title`；标签字符集/长度是否安全 | 当前仅 encoder；需求待确认 |
| TC-ART-006 | **重复合成确定性** | 同文本同参数下发 2~3 次 | 时长/体积/峰值是否稳定；是否需字节级一致 | 未测 |
| TC-ART-007 | 大文件行为 | 整章 8000+ 字 / 15000 字 | 体积/时长是否合理；能否完整下载与播放 | 未测（用例 A09 只查 metadata） |
| TC-ART-008 | VBR/seek 行为 | 拖动进度条到中后段 | 定位准确、无爆音、无静音跳变 | 未测 |
| TC-ART-009 | 首帧/编码器延迟 | 检查 Xing/LAME 头与起始波形 | 起始无异常爆音、无 >100ms 静音 | 未测 |
| TC-ART-010 | **文件命名与唯一性** | 检查 `<taskId>.mp3` 规则 | 不重名、不覆盖；与 taskId 一一对应 | 已确认规则；**覆盖/越权见 SEC-001** |

## 二、音频内容正确性（播放侧，TC-ENC-*）

> 与 `文案格式` 用例互补：那边测"文本怎么进"，这里测"**声音怎么出**"。

| ID | 场景 | 方法 | 判据 | 现状 |
|---|---|---|---|---|
| TC-ENC-001 | **削波 / 真峰值越界** | 峰值、≥0.999 样本数、True Peak | 峰值 ≤0.999；无削波样本 | ❌ 已发现：日语 94/94 越界、最高 1.232 |
| TC-ENC-002 | 响度一致性（LUFS） | 逐文件 LUFS / RMS | 跨语种差 ≤3dB、目标约 −20 dBFS | ❌ 已发现：日语 −11.46 vs 韩语 −16.52（差 5.06dB） |
| TC-ENC-003 | 杂音/齿音/嘶嘶声 | 高频占比 + 人工听测 | <10%，人工无异常 | ⚠️ 全部文件 >10%（24kHz 下阈值需重标定） |
| TC-ENC-004 | **静默空洞** | 逐文件找 >3s 且 metadata 有文本的静默段 | 0 处 | ❌ 已发现：日语 3 文件、韩语 2 文件，最长 82.6s（81.64s 固定占位） |
| TC-ENC-005 | 卡顿 / 断续 / 爆音 | 人工听测（必测项 M2 要求） | 无 | ⏸ 待人工 |
| TC-ENC-006 | 语速一致性 | 任务语速（去空白字/秒）分布 | 同一 voice 稳定（日语 6.4~8.0） | ✅ 已测（可固化） |
| TC-ENC-007 | **首尾漏读** | ASR 核对首句/末句 | 首末句完整 | 未测 |
| TC-ENC-008 | **串任务**（音频内容 ≠ 本任务文案） | 多任务批量 + ASR 交叉比对 | 无串音 | 未测（文本口径 `extra=0` 仅能间接排除） |
| TC-ENC-009 | 数字/日期/金额读法 | 人工 + ASR | 正确率 ≥95% | 未测（用例 N06 提供语料） |
| TC-ENC-010 | 多音字/专有名词发音 | 人工 | 正确率 ≥90% | 未测 |

## 三、产物存储与分发（TC-STO-*）

> MP3 是**存在 COS 上的外链对象**，这一层的问题直接导致"业务拿不到音频"。

| ID | 场景 | 方法 | 判据 | 现状 |
|---|---|---|---|---|
| TC-STO-001 | **立即可获取性（竞态）** | 任务成功后**立即**下载 `audio_url` | 必须 200 且为 MP3 | ❌ 已发现：**18/225（8.0%）返回 `NoSuchKey`（440B XML）**，事后重下均成功 |
| TC-STO-002 | **签名时效与过期重取** | 记录 URL 后延迟 1h/6h/24h 再取 | 过期能按 taskId 重新获取新链接 | ⚠️ 已见 `metadata_url` 过期返回 403；需验证"重新查询能否拿到新签名" |
| TC-STO-003 | 跨区下载质量 | 香港（mp3）与广州（metadata）分别下载 | 成功率 100%、速率稳定、无跨区超时 | ⚠️ 已见 6 次连接重置/超时（重试成功） |
| TC-STO-004 | 响应头正确性 | 检查 `Content-Type/Content-Length/ETag` | `audio/mpeg`、长度与体积一致 | 部分已见（`ct=audio/mpeg`） |
| TC-STO-005 | 断点续传 / 分片 | Range 请求下载大文件 | 支持 Range；续传后文件完整可解码 | 未测 |
| TC-STO-006 | **高并发拉取** | 100~1000 并发下载产物 | 无失败、无限速异常 | 未测 |
| TC-STO-007 | 对象生命周期 | 观察历史批次对象是否被提前清理 | 约定留存期内可访问 | 未测 |
| TC-STO-008 | 重复查询一致性 | 同 taskId 多次查询 | 返回同一对象/一致结果 | 已用于补齐（一致） |
| TC-STO-009 | 上传失败检测 | 任务成功但对象不存在 | 服务端应自检并报错（当前静默） | ❌ 见 STO-001 |

## 九、建议新增的用例编号族与优先级

| 族 | 含义 | 建议优先级 |
|---|---|---|
| `TC-ART-*` | MP3 文件本体（编码/标签/首尾/确定性） | P0：ART-002/003/004；P1：001/005/006/007 |
| `TC-ENC-*` | 音频内容质量（播放侧） | P0：ENC-001/004；P1：002/003/007/008 |
| `TC-STO-*` | 存储与分发 | **P0：STO-001/002**；P1：003/004/008/009 |
| `TC-SEC-*` | 安全与合规 | **P0：SEC-001**；P1：002/004 |
| `TC-STATE-*` | 状态机与生命周期 | P0：STATE-003；P1：002/004/006 |
| `TC-API-*` | 协议与参数 | P1（部分已被 A04/A10 覆盖） |
| `TC-META-*` | metadata/SRT 一致性 | P1：META-001/002/006 |
| `TC-CAP-*` | 容量与成本 | P2 |

> **建议执行顺序**（低成本高信息量优先）：
> ① STO-001/002（秒级、直接决定业务能否取到音频）
> ② ART-002/003/004 + ENC-001/004（本地解码与波形分析，已有脚本可复用）
> ③ STATE-003 + API-001（构造型用例）
> ④ SEC-001（策略确认）
> ⑤ ART-006/007 + CAP-001/002（需成批下发，成本较高）

## 十、与现有 SKILL 的关系

- **已纳入 SKILL**：M0（语料段落结构）、M1（文本口径）、M2（音质，含削波/响度/空洞）、M3（漏词）、M4（切句）、M5（字幕完整性）。
- **本清单新增、SKILL 尚未固化**：`TC-ART-*`、`TC-STO-*`、`TC-SEC-*`、`TC-STATE-*`、`TC-CAP-*`（建议在 SKILL 中新增**「Phase 9 产物与分发」**章节承载）。
- **已发现但尚未固化为回归用例**（建议优先回填）：
  1. 产物可见性竞态（NoSuchKey 18/225）；
  2. 81.64s 固定时长静默占位；
  3. 任务卡死 `status=67` 长时间不收敛；
  4. 日语削波（全部文件峰值 >0.999）；
  5. 段落结构丢失（已固化为 M0 + TC-FMT-A01）。
